# Web 规则与整局验证

从项目根目录运行：

```powershell
node --test development/web-tests/*.test.mjs
node development/web-tools/simulations.mjs
```

测试只创建内存状态，不读取浏览器存储或玩家档案。需要保留机器可读验收结果时，给模拟命令增加 `--output`，路径应位于项目外，例如 `$env:TEMP`。`--quick` 只运行 2 个参考种子和 5 个终局场景，不能替代完整验收。

`helpers/reference-strategy.mjs` 的策略只调用玩家可用的部署、搬迁、维修、升级、节点和奖励命令，遵守实际费用和带宽。它会在新入口开放时重新评估火力覆盖；没有补充资源、直接扣敌人生命、刷新奖励或跳过首领。模拟器记录执行前后的核心源码 SHA-256；运行期间改动核心文件会使验收失败。

完整模拟曾复现 `reference-12` 和 `terminal-19` 的永久僵持：猎杀敌人在防线射程外不停攻击被持续维修的构造。当前规则中，猎杀和攻城敌人每射击三次后会显示提示并推进 2.5 秒；贴身近战仍然能够阻挡。战斗测试保留了这个局部复现，完整种子仍保留在验收集合中。游戏没有使用总时长上限强行判定胜败；测试中的 360 秒界限只用来报告卡局。

无界面测试不能证明画面、音频、真实操作和发布入口可用；这些仍需在实际浏览器和发布版本中单独验证。

难度改动使用 `difficulty-sweep.mjs` 记录各幕伤害、突破、损毁、战斗时长和构筑，并逐节点核对跨难度的计划敌人数与增援预算。`--strategy` 可选 `reference`、`defensive`、`opening`、`empty`；后两者用于验证缺少成长或部署时的失败流程。所有结果必须到达终态且源码哈希一致。实际命令、数值表和样本结果见 [难度与平衡说明](../../docs/DIFFICULTY_BALANCE.md)。参考策略的样本胜率不能当作真实玩家胜率。

# 构造与敌人的模型和动作

战场使用 Three.js 实时绘制金属机械模型，地形与规则反馈继续由 Canvas 2D 合成。近景模型具有倒角、加权法线、表面磨损、环境反射和部件阴影。玩家可以连续旋转镜头并放大观察，模型朝向和关节动作随画面刷新。

## 内容与表现

| 内容 | 外观 | 连续动作 |
| --- | --- | --- |
| 12 种防御构造 | 每种有 T1、T2A、T2B、T3A、T3B，共 60 种 | 近战出手、炮管后坐、迫击炮抬升、无人机发射、维修臂与支援机构展开 |
| 24 种普通敌人、7 种精英 | 连续壳体、承重骨架与独立职责装置，共 31 种 | 接地步足、行程滚轮、支撑式虫体推进、飞行舵面、完整攻击工作行程、能力蓄力与释放 |
| 6 种首领 | 每名首领三阶段，共 18 种 | 有轴座的护门、侧通道、翼面与冠架逐阶段展开，专属机构使用同一战斗时钟 |

总计 49 类实体、109 种外观。实体沿用经过授权的 Kenney 机械零件，驱动轮在保留铸造轮芯的基础上增加胎肩、轮辋和紧固件。构造保留青绿色能源标识，敌人使用珊瑚色信号标识；角色主要通过轮廓与部件区分。

仓库、图鉴、详情和升级预览使用同一模型渲染的 256 像素肖像。五种塔变体共用透明边界取景，保留升级前后的体量差异。付费升级和事件免费升阶均显示将要获得的分支模型。

命中特效继续区分短弧、射线、抛物线、无人机航迹、连锁和维修连线。受击由承重或工作关节吸收短行程。每种敌人有独立卸载、失压或折叠死亡动作，在 0.65 战斗秒内消散；飞行残骸同步失去飞行高度。损毁构造留下可维修残骸。过载构造变暗并显示“停机”。

规则修订 4 的无人机织机发射独立追踪机体，复用有许可的飞行器零件。机体位置和方向来自战斗状态，命中时才结算伤害。双机、目标切换、发射源停机、追击时限与暂停均使用同一套规则，具体数值见[战术更新](TACTICAL_UPDATE.md)。

## 动画与规则

`web/view/entity-motion.js` 消费核心事件中的身份、目标、朝向和战斗时间。敌人的模型权威来源是 `development/assets/enemy_rework/<id>.mjs`，每种怪物由一个独立作者制作；动作位于 `web/view/enemy-animations/<id>.js`。编译器生成运行模型索引与动作注册表，保留 12 类建筑配方。

敌人采用父子关节层级。步足按实际行程进行支撑和回摆，髋、膝、踝配合承重。64 段圆弧轮胎按真实接触高度积分滚动，近远景共用同一接触轮廓。飞行器通过推进喷口、舵面与能力机构工作。攻击依次经过蓄势、接触或释放、后坐和复位。模型动作保持规则的命中、伤害、冷却和随机结果。

能力预警按真实开始和结束时间计算进度，释放发生在显示插值到达对应事件时。持续能力时长来自自身能力的截止时间，队友加速保留为移动状态。施法与实际移动可同时发生，行走和传动持续工作。

20 Hz 模拟与画面刷新之间采用最多 50 毫秒的显示插值，同时平滑移动位置与关节相位。瞬移保持跳跃表现。暂停与确认弹窗冻结显示时钟，1／2／3 倍速同步。读档、切换战场或时钟回退会清理旧动作与消散记录。

“减少动态效果”固定行走、悬浮和出手姿态，关闭受击闪动与生成缩放。停机、首领阶段、命中连线和能力预警继续可见。敌人死亡快照和飞行高度仍来自真实战斗事件。

## 渲染结构与资源

`web/view/entity-renderer.js` 使用正交相机，55° 俯角与 Canvas 的投影和拾取坐标一致。地形生成只写深度的遮挡网格；高地侧壁也参与遮挡。血条、状态与技能范围在模型合成后绘制。

相同零件、阵营、材质和细节等级共用 `InstancedMesh`。四个并发加载任务读取 50 个 GLB，每个文件同时包含两级几何。屏幕主体尺寸达到 54 CSS 像素时使用近景网格，包括五段倒角和细化曲面。远景保留圆滑轮廓，省略小型紧固件。阴影只在模型姿态、位置、外观或地形改变时更新。死亡消散使用独立透明批次，并同步降低能源发光；制作头像和死亡图集时保留完整不透明深度。

成对部件通过 `mirrorX` 反射源顶点、法线及三角形绕序，保留正尺寸实例。反射网格按源表面和细节等级缓存，并在渲染器销毁时释放。建筑的成对模块也使用同一规则；T3 在既有安装位强化模块，以低位承板形成新的层次。

## 复现

制作工具与中间输出放在项目外。游戏运行无需 Blender 或 npm 安装。

```powershell
# 编译全部 37 个敌人定义与独立动作。
node .\development\web-tools\build-enemy-models.mjs

# 生成两级 GLB 和组装索引，当前验证版本为 Blender 4.5.9。
& '路径\blender.exe' --background --python .\development\web-tools\export-realtime-models.py -- --output "$env:TEMP\mindrealm-realtime-models"

# 只修改装配时增加 --definitions-only，复用当前 GLB 并输出新索引。

# 在仓库外安装固定版本的 three 与 esbuild，传入该 package.json 所在目录。
node .\development\web-tools\bundle-three.mjs '外部依赖目录'

# 将检查通过的 GLB 和 models.json 复制到 assets/game/models 后，
# 在独立 QA 浏览器运行 export-model-presentation.js，下载 49 张肖像到执行目录。
# URL 增加 bakeEnvironment=1 时，同时从原始 HDR 重新烘焙环境光。
python -X utf8 .\development\web-tools\index-model-portraits.py "$env:TEMP\mindrealm-realtime-art\portraits"

node .\development\web-tools\refresh-asset-manifest.mjs --write
npm test
npm run verify
```

`export-model-presentation.js` 通过 Playwright CLI 的 `run-code --filename` 执行。它要求独立回环端口和 `?qa=1`，执行目录应设为系统临时目录。环境光烘焙属于制作步骤，检查完成后替换运行文件。

模型制作页位于开发服务器的 `/development/enemy-review`。`window.enemyReview.bake(ids)` 返回指定敌人或建筑的原始 PNG 数据。通过 `export-enemy-review.ps1` 写入仓库外的本地 JSON，再用 `install-enemy-art.py` 解码。图片批处理、像素检查与文件复制均在本机完成。肖像索引器支持 `--ids=<列表>` 限定更新范围，`measure-entity-bounds.py` 更新后备图集取景，最后统一刷新资源清单。结构审查使用近景多角度与动作关键帧，并与 T3 建筑比较。

制作页可选择首领的三个阶段、能力预警与释放，并查看施法期间的持续行进。稳定飞行模型在同一推进指令下保持固定机身姿态；`window.enemyReview.flightResponse(ids)` 用相同时间与行程、不同实际速度指令检查喷口和舵面响应。图集记录见 `development/assets/enemy_rework/ART_PROVENANCE.json`。

圆轮在 80 像素图集中的轮廓变化很小。`window.enemyReview.rollingResponse(ids)` 固定世界位置、时钟和速度，用不同实际行程检查 512 像素近景中的轮毂转动。它与真实 GLB 接地检查共同验证滚动。当前装配和图集记录见 `development/assets/model_sources/SYMMETRY_REFINEMENT.json`，此前曲面网格的制作记录保留在 `SURFACE_REFINEMENT.json`。

`enemy-rig.test.mjs` 覆盖独立定义与运行索引的一致性、纯姿态与暂停、实际 GLB 轮缘接地和无滑动、冲刺起始连续性与固定死亡末姿。完成修改后与其他检查集中执行一次，制作期间只抽查必要样本。

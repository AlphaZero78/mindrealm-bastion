# 构造与敌人的模型和动作

战场使用 Three.js 实时绘制金属机械模型，地形与规则反馈继续由 Canvas 2D 合成。近景模型具有倒角、加权法线、表面磨损、环境反射和部件阴影。玩家可以连续旋转镜头并放大观察，模型朝向和关节动作随画面刷新。

## 内容与表现

| 内容 | 外观 | 连续动作 |
| --- | --- | --- |
| 12 种防御构造 | 每种有 T1、T2A、T2B、T3A、T3B，共 60 种 | 近战出手、炮管后坐、迫击炮抬升、无人机发射、维修臂与支援机构展开 |
| 24 种普通敌人、7 种精英 | 按职责区分护盾、装甲、步足、履带、发射器和信号设备，共 31 种 | 步足交替、轮轴转动、虫体节段摆动、悬浮、攻击、能力蓄力与释放 |
| 6 种首领 | 每名首领三阶段，共 18 种 | 阶段增加护板、环带或机械结构，移动、攻击与施法使用同一动作时钟 |

总计 49 类实体、109 种外观。所有实体使用经过授权的 Kenney 机械零件组装。构造保留青绿色能源标识，敌人使用珊瑚色信号标识；角色主要通过轮廓与部件区分。

仓库、图鉴、详情和升级预览使用同一模型渲染的 256 像素肖像。五种塔变体共用透明边界取景，保留升级前后的体量差异。付费升级和事件免费升阶均显示将要获得的分支模型。

命中特效继续区分短弧、射线、抛物线、无人机航迹、连锁和维修连线。受击时模型短暂亮起；敌人倒下后倾斜、收缩并在 0.65 战斗秒内消散。损毁构造留下可维修残骸。过载构造变暗并显示“停机”。

规则修订 4 的无人机织机发射独立追踪机体，复用有许可的飞行器零件。机体位置和方向来自战斗状态，命中时才结算伤害。双机、目标切换、发射源停机、追击时限与暂停均使用同一套规则，具体数值见[战术更新](TACTICAL_UPDATE.md)。

## 动画与规则

`web/view/entity-motion.js` 消费核心事件中的身份、目标、朝向和战斗时间。行走相位来自实际移动距离。攻击与施法使用各部件的连续变换；模型表现保持规则的命中、伤害、冷却和随机结果。

20 Hz 模拟与画面刷新之间采用最多 50 毫秒的显示插值，同时平滑移动位置与关节相位。瞬移保持跳跃表现。暂停与确认弹窗冻结显示时钟，1／2／3 倍速同步。读档、切换战场或时钟回退会清理旧动作与消散记录。

“减少动态效果”固定行走、悬浮和出手姿态，关闭受击闪动与生成缩放。停机、首领阶段、命中连线和能力预警继续可见。敌人死亡快照和飞行高度仍来自真实战斗事件。

## 渲染结构与资源

`web/view/entity-renderer.js` 使用正交相机，55° 俯角与 Canvas 的投影和拾取坐标一致。地形生成只写深度的遮挡网格；高地侧壁也参与遮挡。血条、状态与技能范围在模型合成后绘制。

相同零件、阵营、材质和细节等级共用 `InstancedMesh`。四个并发加载任务读取 49 个 GLB，每个文件同时包含两级几何。屏幕主体尺寸达到 54 CSS 像素时使用近景倒角网格，远处使用原始网格，并跳过小型紧固件。阴影只在模型姿态、位置、外观或地形改变时更新。

| 路径 | 用途 |
| --- | --- |
| `assets/game/models/` | 49 个内嵌几何 GLB 和 `models.json` 组装配方；合计 4,582,121 字节 |
| `assets/game/portraits/` | 49 张透明肖像图集，109 个 256×256 帧；合计 4,522,313 字节 |
| `assets/game/lighting/studio_small_09_pmrem.bin` | 768×1024 RGBA16F 环境光，6,291,456 字节，运行时直接上传 |
| `assets/third_party/polyhaven/` | Studio Small 09 原始 HDR，以及 Blue Metal Plate 原始 1K 颜色、法线和粗糙度纹理及许可 |
| `assets/third_party/three/` | Three.js 0.186.1 的本地模块包与 MIT 许可 |
| `development/assets/model_sources/kenney/` | 保留的 CC0 模型源与许可 |
| `development/web-tools/bake-entity-art.py` | 已验证的 49 类机械组装配方 |
| `development/web-tools/export-realtime-models.py` | 焊接顶点接缝、三段倒角、加权法线、UV 与两级几何导出 |
| `web/view/model-portraits.js` | 肖像尺寸、帧数和共享透明边界 |

原始 HDR 保留供制作时重新烘焙；游戏加载预先过滤的环境光，省去启动时的 GPU 滤波。旧 80 像素图集保留供图形初始化失败时回退和源资产检查；正常实时渲染不会预加载这些动作图集。图形初始化失败会显示明确提示。

## 复现

制作工具与中间输出放在项目外。游戏运行无需 Blender 或 npm 安装。

```powershell
# 生成两级 GLB 和组装索引，当前验证版本为 Blender 4.5.9。
& '路径\blender.exe' --background --python .\development\web-tools\export-realtime-models.py -- --output "$env:TEMP\mindrealm-realtime-models"

# 在仓库外安装固定版本的 three 与 esbuild，传入该 package.json 所在目录。
node .\development\web-tools\bundle-three.mjs '外部依赖目录'

# 将检查通过的 GLB 和 models.json 复制到 assets/game/models 后，
# 在独立 QA 浏览器运行 export-model-presentation.js，下载 49 张肖像到执行目录。
# URL 增加 bakeEnvironment=1 时，同时从原始 HDR 重新烘焙环境光。
python -X utf8 .\development\web-tools\index-model-portraits.py "$env:TEMP\mindrealm-realtime-art\portraits"

node .\development\web-tools\refresh-asset-manifest.mjs --write
npm test
npm run verify
```

`export-model-presentation.js` 通过 Playwright CLI 的 `run-code --filename` 执行。它要求独立回环端口和 `?qa=1`，执行目录应设为系统临时目录。环境光烘焙属于制作步骤；批准新的烘焙结果后，再替换运行文件。

## 当前验证

2026-10-04，234 项 Node 测试通过。资源核验通过 311 项必要文件、357 项 SHA-256 和 10 份许可证。模型专项覆盖 49 个 GLB 的两级几何、法线与 UV、109 个变体的引用和 49 张肖像尺寸。

`browser-realtime-validation.js` 通过 23 项实际浏览器检查：109 种外观均能渲染且分支各异，49 类模型具有有效关节动作，37 类敌人持续移动，停机及减少动态效果固定相应变换。升级 A/B 预览、取消、确认 B、T3B 方向和读档后的同一部署模型均通过。

实际 1／2／3 倍速各采样约 0.90 秒，模拟分别前进 0.95／1.85／2.70 秒，包含固定步长采样边界。显示时钟与插值目标的误差为 0，暂停期间模型变换完全相同。经验条在实际击杀后进入深度 2，显示 9／800；八种游戏阶段的经验栏另通过 72 组窗口与缩放检查。

`browser-tactical-combat.js` 通过 7 项实时战斗检查。2.2 秒追踪样本记录 55 个机体位置、52 个朝向、6 个机体身份和 4 次命中，累计伤害 147.808。暂停后机体与规则状态保持一致。首领破阵预警、推进、击败后清场及后续失败的记录保留也通过。

完整浏览器流程从新局完成 48 个路线节点、三次枢纽和三名首领，进入胜利结算。每幕普通战与首领战分别采集真实 RAF 动作；较长战斗用 QA 固定步长推进。画面与音频错误列表为空。120 个内存模拟场景也全部到达预期胜负终态，源码哈希守卫通过。

## 性能测量边界

环境为 Windows、Chromium、RTX 5060 Laptop、ANGLE D3D11。压力场景同时绘制 24 座 T3 构造、100 个移动敌人和 96 架追踪无人机，覆盖 49 类实体，并使用多名首领增加压力。镜头容纳完整战场，预热 45 帧后测量 180 帧。

| 窗口 | CPU 绘制中位数 / P95 | RAF 间隔中位数 / P95 |
| --- | --- | --- |
| 1440×900 | 2.1 / 2.5 毫秒 | 4.2 / 4.3 毫秒 |
| 1920×1080 | 2.1 / 2.6 毫秒 | 4.2 / 4.3 毫秒 |

1920 场景为 334 次绘制调用、1,644,488 个三角形，含阴影绘制；28 个实体使用近景模型，192 个使用远景模型。相机与 Canvas 坐标在五种角度和三个高度上的最大差为约 6.71×10⁻¹³ 像素。

这是 `browser-model-performance.js` 的渲染压力样本，包含主动更新的位移，未计入完整战斗 AI 的逐帧开销。结果只代表上述设备，低端显卡尚待实测。原始报告与截图位于系统临时目录；仓库保留复现脚本。

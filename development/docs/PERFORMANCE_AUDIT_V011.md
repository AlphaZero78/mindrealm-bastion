# v0.1.1 项目审计与性能验证

## 范围与基线

2026-10-02。本轮审计覆盖运行规则、战斗、进度与存档、输入与界面、渲染、音频、资源授权、本地 HTTP 服务、Windows 启动器及发布工具。

性能对照基线是本轮开始时的本地版本，已包含[十项交互改进](EXPERIENCE_UPDATE.md)。这部分交互改进与本轮优化共同进入 v0.1.1。对照使用相同模型、动画、特效、音乐、字体、分辨率及敌人数量。

## 审计结果与处理

| 范围 | 发现与处理 | 证据 |
| --- | --- | --- |
| 渲染与规则查询 | 一次绘制中会重复计算同一构造的属性。绘制期间复用规则缓存，成功和异常退出都会释放缓存。 | 缓存失效回归；60 组像素与实体几何对照。 |
| 射线与占地 | 每次直接攻击判定都构造占地字符串集合。整格矩形改用边界比较；非整数输入保留集合判定。 | 9,600 次攻击判定逐字段相同。 |
| 构筑效果 | 每次汇总都重复枚举全部收藏品和天赋。预先收集效果名称，按次创建独立数值结果。 | 240 组效果对照；完整战斗结果对照。 |
| 地形重建 | 包围盒计算会创建多个临时数组。改为遍历顶面与侧面的顶点累积边界。 | 各视角像素哈希相同；性能采样。 |
| 战斗与路线 | 审查种子随机、资源扣费、过载、目标与视线、增援预算、首领终态及奖励顺序。维持现有数值与固定步长。 | 120 局模拟；浏览器 48 节点通关。 |
| 存档 | 字符串形式的属性增益曾可通过校验，并产生无效射程。新增增益、单位元数据和地形退款记录的结构检查，拒绝覆盖有效存档。 | 损坏输入回归；缺少可选字段的旧存档仍可保存、读取。 |
| 本地 HTTP 服务 | 解码后的路径可能越过 URL 前缀检查。现在验证规范路径与物理路径，限定在公开目录；QA 辅助文件仅在显式 QA 模式开放。 | 编码斜线、反斜线、目录链接、越界、缺失文件和请求方法测试。 |
| 本地资源读取 | HEAD 曾读取整份资源后丢弃正文。现在只读取元数据，并支持 ETag 条件请求；文件变化后返回新内容。 | HEAD、304、同长度内容更新与健康检查测试。 |
| 音频 | Windows PowerShell 5.1 曾把 FFmpeg 的正常 stderr 信息当作异常。使用原生进程流读取，并依据退出码判定。 | 两条音乐的响度、峰值及同步时长通过；音频单元测试和真实浏览器流程。 |
| 界面与输入 | 审查路线直达、拖动、旋转、草稿改地、升级、收栏、转场、分辨率及恢复存档。更新旧测试中的节点与地形交互步骤。 | 194 项浏览器检查，覆盖正常、取消、失败及小窗口。 |
| 资源与发布 | 保持图集、音乐、字体和许可证原字节；补全新模块的必需文件检查。 | 120 项必需资源、173 项哈希、7 项许可证；25 项 EXE 启动器检查。 |

存档格式和本机存储命名空间继续使用 Web v2。正常旧存档沿用原有路线、资源、随机顺序与已部署方向；自动验证使用独立浏览器、隔离端口及内存状态。

## 性能测量

测量设备为 RTX 5060 Laptop，浏览器为 Chromium 154。下面的压力场景使用 1920×1080 窗口，保持 35 座构造、100 个活动敌人和 6 名首领，持续旋转镜头，并每秒使地形缓存失效 4 次。每次采样 1000 个帧间隔；同时启用 CPU 采样器。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 平均绘制耗时 | 8.75 ms | 7.20 ms |
| 绘制耗时 P95 | 13.40 ms | 10.60 ms |
| 绘制耗时 P99 | 16.30 ms | 13.10 ms |
| 平均帧率 | 44.78 FPS | 46.81 FPS |
| 1% low | 27.24 FPS | 27.88 FPS |

本次动态压力样本的平均绘制耗时降低约 18%，P95 降低约 21%。整体帧率提升有限，极端负载仍有掉帧。

另以完全相同的静止战况进行成对测试：每次切换镜头，定期刷新范围，每种视图预热 4 次并测量 20 次，两端各取得 1200 个样本。平均耗时为 10.49 ms 与 10.48 ms，P95 为 30.60 ms 与 31.90 ms。这组持续提交绘制指令的测试中，总体收益接近零。因此性能结论限定在已记录场景；当前 Canvas 合成与图像绘制仍占较大开销。

## 功能与画面一致性

独立对照取得以下结果：

- 180 项源码测试通过，覆盖正常、取消、失败、边界及本轮审计复现。
- 9,600 次攻击判定及 240 组构筑效果逐字段相同。
- 两个种子在压力 0、5、10 下的六局完整远征，优化前后状态和战斗记录一致，均完成 48 节点。
- 两种窗口尺寸、六个视角及远程、支援、过载、低精神、部署预览，共 60 组画面。像素 SHA-256、动作帧、方向、尺寸和位置全部一致；绘制没有修改游戏状态。对照前统一中间画布的初始状态，消除历史分配对截图的影响。
- 120 局回归全部正常结束：20 个标准参考种子全部获胜；另 100 局为 57 胜、43 败，其中 20 个空阵均败。源码哈希守卫和失败列表为空。
- 真实浏览器逐节点完成三幕、48 节点和三名首领，结算成功，脚本、渲染及音频错误列表为空。部署使用合法参考命令，战斗通过实际固定步长模拟加速。

两条战斗音乐均为 −18 LUFS，时长均为 203.911837 秒；真峰值分别为 −3.8 dBTP 和 −4.5 dBTP。运行资源保持既有授权文件的原始哈希。

## 复验与发布边界

常规验证使用 `npm test`、`npm run verify`、`simulations.mjs` 和既有 Playwright CLI 工作流。新增 `compare-core.mjs --baseline <外置基线目录>` 用于规则与完整远征对照；`browser-render-equivalence.js` 比较独立 QA 服务的 4190、4191 端口。原始基线、结果与截图位于系统临时目录 `mindrealm-v011-qa`，发布包与临时文件均保存在源码目录外。

本轮维持启动器对 4173 端口上有效游戏服务的复用行为。运行多个版本时，该端口会继续提供当前服务目录中的内容；更换版本前应先结束旧目录对应的游戏服务，再启动新目录。使用相同浏览器和端口可继续本机存档。

本报告记录本机验证范围。其他硬件与浏览器的帧率需要在相同场景中另行测量。

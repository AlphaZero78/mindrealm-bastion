# 三入口战场与战术规则更新

本轮源码采用规则修订 4，围绕范围可读性、防线规模、地形规划和三幕推进调整体验，随 v0.1.3 发布。后续 36 幅 CG 的写实风格重绘及发布包验收见 [v0.1.3 更新](RELEASE_V013.md)。

## 战场与操作

新局保留北、西、东三个入口，入口位置沿边随机变化。火种移到南侧旧入口区域，中心为（20，38），5×5 保护区完整位于 41×41 战场内。

地形在交错山脊、离散台群、环形洼地、双脊峡谷和破碎高原中选择，再生成不同山脊、支路和高台。初始通路均为零高度，相邻高差最多一级。火种附近保留可用高台，开局三个远程构造可免费部署。

同一组 32 个固定种子的前后比较中，高地格数的标准差从 83.45 增至 183.25，种子间平均高度差异比例从 58.12% 增至 65.32%。入口布局从一种增至 32 种，覆盖全部五类地貌。这组统计用于检查生成差异；通路与部署可用性另行验证。

地形工具默认拖动框选。左键拖出矩形，中键移动视角，松开后添加一笔草稿。预览显示格数、累计费用、通路和屏障；确认后统一扣费。框内存在保护区、已部署构造或费用不足时，整笔保持原样。Esc、右键和窗口失焦可取消正在拖动的选区；确认后的整块修改可一次撤销并原额退款。

战前的金色点线表示陆路，蓝色箭头表示飞行路线。每条线带名称和敌人数，左侧编队也分列陆、空数量。飞行路线按入口直达火种，陆路依据实际寻路和地形草稿更新。

背包超容量时可以先领取完奖励，再整理构造。进入下一节点或下一幕前须恢复到容量以内。维修、撤回和部署继续使用原有维护规则。

## 三幕敌群与攻击表现

普通编队按幕使用各自的敌人池，每幕有八种普通或功能敌人。边境强调冲刺与护航，工厂强调维修、复制和盾阵，核心强调重甲、干扰和攻城。第二、三幕的生命与攻击在既有成长上再乘 1.12 / 1.24。

| 幕 | 新增敌人 | 应对重点 |
| --- | --- | --- |
| 噪声边境 | 废响重盾、回声滑翔翼、噪声丧钟 | 破甲、对空集火、远距离处理压力场 |
| 记忆工厂 | 记忆赶工者、修复穿梭艇、档案典狱长 | 拦截突击、切断空中维修、集中穿透群体护盾 |
| 统御核心 | 秩序重卫、缄默巡翼、熵蚀攻城机 | 应对重甲穿透、预留带宽、分散防线并守住高地 |

目录现有 24 种普通或功能敌人、7 种精英和 6 名首领，共 37 种敌人。新增九种模型继续使用有许可的 Kenney 零件，拥有独立结构、移动与技能动作。全部 49 类构造和敌人共用 49 个零件文件，包含 109 种阶级或阶段外观。

无人机织机在新局发射独立追踪机体，飞行中更新方向，命中时结算伤害。原目标消失后，尝试锁定发射源范围内的另一目标。A 分支追加一架攻击另一目标的无人机，伤害为 60%；B 分支命中后标记。发射源损毁或停机后终止追击。单次追击最长 4 战斗秒，同时最多 96 架。

无人机模型与拖尾按模拟位置插值，暂停后冻结。脉冲弹、聚焦射线、迫击炮弧线、近战斩击、壁垒震荡、铆钉冲击与维修连线分别表达攻击职责。

## 事件与精神使者

新局按幕提高事件交换幅度。负资源代价使用基础的 1.5 / 1.65 / 1.8 倍，正收益使用 1.6 / 1.8 / 2 倍，再按资源取整。免费升级由一次增至两次，原两次增至三次；维修、扩容与赠物也有对应增强，准确得失在确认前列出。

精神恢复始终显示完整整数，实际恢复按上限截断。例如静默室显示“精神 +40”，当前 99.4 / 100 时仍显示 +40，生效后为 100 / 100。致命提示同时计入该选项的最大精神成长，避免误判结果。

12 位精神使者各有六件专属收藏品，共 72 件。每次相遇按种子抽取三件，再选择一件。三幕的候选在新局时确定，保存和继续均保留同一组候选。旧存档已经确定的三件赠礼继续保留。

## 首领清场与幕间等待

击败首领后，战斗继续等待全部计划敌人与合法增援清理完毕。界面显示“首领已击败 · 清理余敌”，余敌造成致命精神伤害时仍会失败。首领击败记录、档案和对应碎片在失败结算中保留。

完整模拟曾发现治疗首领与维修防线相互维持的僵局。新局的地面首领攻击构造六次后，预警 1.1 秒，再进行 2.5 秒破阵推进。期间越过构造阻挡、抵抗定身，移速提高 20%。详情页提前公开规则，战场显示倒计时和推进方向。原先卡住的状态在修复后 40.05 战斗秒内正常结束。

前两幕清场并领取完奖励后，播放远景推移与淡入动画。页面停留在幕间，玩家点击“进入第 N 幕”才进入下一幕的心神枢纽。幕间可以检查背包，继续游戏也恢复这项等待。减少动态效果设置会关闭装饰动画。第三幕清场后进入胜利结算。

## 保存与实现边界

新局使用 `difficultyRevision: 4` 和地形生成 2。旧局保留原四入口地形、火种位置、敌人编队、事件数值和每级带宽成长。已有构造全部保留，背包按当前总数显示。正式存档命名空间和 Web v2 结构版本保持不变。

使用 v0.1.2 源码及其原保存器生成枢纽、路线、战前、事件、商店、奖励六种测试存档。当前保存器读取后，与旧保存器的回读结果逐项一致。验证使用独立内存存储。

规则由 `world.js`、`rules.js`、`battle.js`、`difficulty.js`、`event-balance.js` 与 `state.js` 提供。界面消费同一份光环、预览和战斗状态。截图、日志、源模型导出中间文件与测试构建位于仓库外。

## 验证方法

```powershell
npm test
npm run verify
node .\development\web-tools\simulations.mjs --output "$env:TEMP\mindrealm-tactical-simulations.json"
```

`development/web-tests` 中的浏览器脚本通过 Playwright CLI 的 `run-code --filename` 执行，使用独立回环端口和 `?qa=1`。`browser-tactical-flow.js` 验证交互及经验栏，`browser-tactical-combat.js` 验证无人机、破阵与首领击败后的流程。`browser-event-stories.js`、`browser-nexus-catalog.js`、`browser-nexus-layout.js` 检查事件、赠礼与节点布局。

`browser-full-run.js` 在同一页面按幕执行，使用公开规则命令部署，长战斗通过固定步长加速，代表性战斗另外采集真实画面刷新。`browser-model-performance.js` 覆盖 100 敌人、24 座 T3 构造及 96 架无人机的渲染压力，包含全部 49 类实体。

标准模拟组为 18 胜、2 败，100 个混合策略场景为 29 胜、71 败，其中 20 个空防线场景全部失败。这些结果用于验证推进、胜负和边界处理，胜率只代表脚本策略。浏览器整局在六场代表性战斗采集实际画面刷新，其余较长过程使用固定步长推进。

实时攻击专项采用固定敌人和增强耐久等测试条件，用于测量追踪、暂停、预警和结算。正常整局的证据来自独立的浏览器远征及模拟矩阵。

构建版控制台、画面和音频错误列表为空，外网请求为 0。上述临时构建记录对应战术规则验收；v0.1.3 的最终 CG、压缩包及发布检查记录于 [v0.1.3 更新](RELEASE_V013.md)。

RTX 5060 Laptop 的渲染压力样本包含 220 个实体，1440×900 与 1920×1080 的 CPU 绘制 P95 分别为 2.5 和 2.6 毫秒。测量范围与复现方式见[模型和动作](ENTITY_MODELS_AND_ANIMATION.md#性能测量边界)；完整战斗 AI 开销与其他显卡性能需分别测量。

# 浏览器重构的规则与交付边界

本次重构依据根目录 AGENTS.md、`plans/01_FULL_LAUNCH_PLAN.md`、`plans/02_PIXEL_REMAKE_PLAN.md`。两份原计划完整保留。后制定的像素重制计划覆盖首份计划相应条目，用户本次允许更换引擎的要求覆盖原计划的 Godot 限制。

## 保留的玩法

- 三幕分别为17、16、15层；每幕有独立首领，第三幕首领死亡后立即结算。
- 41×41持久微网格、5×5火种、0—4级高度、斜坡与可破坏峭壁。多格占地，三种地形笔刷，2专注/实际变化格，撤销退款。
- 开局100精神、99专注、20带宽、深度1、3近战/3远程/1支援。战前操作，战中锁定；暂停和1/2/3倍速度。
- 12种构造及A/B分支、18种普通/功能敌人、4精英、6首领、30收藏品、24天赋与24事件。收藏品中的6件与6个事件通过记忆碎片扩展后续内容池。
- 路线、未知节点、货架、奖励均由种子确定；各节点提供不同的服务。奖励按单位、收藏品、天赋顺序领取。
- 死亡压力平方衰减、抗性直接抵消、逆部署顺序过载禁用、有限增援、维修回仓库、按耐久比例融合。

## 本次明确替代的技术方案

| 原计划 | 浏览器重构方案 | 原因与玩家收益 | 对单局的影响 |
|---|---|---|---|
| Godot/GDScript、Godot场景与Windows导出 | 原生JavaScript模块、Canvas正交三维投影、像素图集、Web Audio；Node只提供本地静态文件 | 无需安装或启动Godot，代码与数据可直接审查；发布包可离线启动 | 规则与战斗模拟独立于绘制，仍固定20Hz |
| 全界面固定640×360并整体整数放大 | 战场以CSS实际尺寸与最多1.5倍DPR绘制，图集独立最近邻；信息栏和战场分区，DOM界面可缩放 | 按用户清晰度反馈替代旧降采样；图集保持像素风格，文字/地形不再一起放大，支持100/125/150%设置 | 不改变判定；窗口变小时自动限制过大的界面缩放，保留必要操作空间 |
| 窗口化、无边框/独占全屏、引擎VSync与固定分辨率列表 | 可调整大小的浏览器窗口、浏览器全屏；显示刷新由requestAnimationFrame与浏览器管理 | 保留缩放与全屏需求，避免暴露浏览器无法可靠控制的驱动设置 | 不改变固定步长或战斗速度 |
| Godot用户目录存档、清除旧开发档 | 当前浏览器独立v2命名空间，完整性校验、备份、待提交写入；旧Web/Godot数据保留且不读取作验证 | 隔离引擎迁移，避免误伤已有用户数据 | 不兼容旧版单局；新版战中退出仍返回战前快照 |
| 刺耳战斗循环或节点切换后直接替换音乐 | 已授权calm/action同步双层、等功率平滑混合、曲目实测响度补偿、低通和压缩 | 危险度变化可听，降低尖锐与突兀的切换 | 音乐不参与规则随机流 |
| 猎杀者可无限停在一个远距目标前射击 | 猎杀/攻城单位有限齐射后带提示继续推进，贴身近战阻挡仍生效 | 防止射程外敌人与维修构造形成永久互耗；玩家可预判移动窗口 | 加强火种方向的持续压力，未设置自动胜利或战斗超时结算 |

| 固定四块方形高台与直十字道路 | 随种子变化的自然山脊、平台和弯曲零高度谷道 | 按用户要求增加地形与部署选择，四入口保证通路，初始远程有可用平坦高台 | 只作用于新局；不改旧存档、开局资源、路线与奖励 |

本次体验修正与最新验证见[更新记录](CLARITY_UPDATE.md)。

## 数据与资源

所有运行代码重新编写。已核验许可的PNG图集、字体与音频继续使用；它们属于引擎无关资源。GLB模型源与对应许可用于保留素材来源，不属于可运行Godot版本。

新版不读取或修改Godot玩家的存档、设置。自动验证使用内存存储或独立浏览器会话；浏览器QA模式必须显式启用，仅用于开发验证，不出现在正常操作流中。

Godot工程、GDScript、场景、导出配置、旧构建工具和旧发布包仅在新版完整验证后删除。不会卸载系统中的通用工具，也不会删除不属于此项目的文件。

## 验证原则

规则测试、完整种子模拟、实际浏览器操作和渲染性能分别提供证据。无界面模拟不能证明真实画面性能；当前机器的结果不能直接宣称为GTX1050实测。每次发布必须记录实际测试范围、运行机器、源码哈希及未验证的硬件目标。

# 《心域防线》从零开发完整首发计划

## 总体方案

- 在空白目录中使用标准版 GDScript 和当前稳定的 [Godot 4.7.2](https://godotengine.org/download/windows/) 从零建设，不复制旧工程的代码、资源、场景或数值。
- 首发为 Windows x64 简体中文单机游戏，键鼠操作，目标配置为 GTX 1050 级显卡在 1080p 中画质稳定 60 FPS。
- 将 AGENTS.md 的“第17层最终战”替换为三幕完整单局：第一幕17层、第二幕16层、第三幕15层，每幕末尾一名首领，总计约48个节点、120–180分钟；这是对当前《杀戮尖塔2》三幕地图节奏的塔防化实现。[结构参考](https://spire-codex.com/ptb/mechanics/map-generation)
- 三幕分别为“噪声边境”“记忆工厂”“统御核心”，每幕从两名主题首领中按种子确定一名，共六名首领；在幕初、宝库附近和首领前营地逐步公开其威胁情报。
- 实现标准难度及通关后逐级解锁的10级“控制压力”，局外成长只扩展内容池、档案和难度，不强化基础开局属性。

## 工程结构与核心接口

```text
D:\game_build
├─ project.godot / AGENTS.md / README.md
├─ src
│  ├─ app / run / map / rules / battle
│  ├─ terrain / units / enemies / progression
│  ├─ save / ui / audio / shared
├─ scenes
│  ├─ app / map / battle / nodes / ui
├─ content
│  ├─ acts / units / enemies / bosses / encounters
│  ├─ relics / talents / events / localization
├─ assets
│  ├─ game
│  │  ├─ materials / vfx / icons / audio
│  └─ third_party
│     ├─ quaternius / kenney / polyhaven / opengameart
├─ tests
│  ├─ unit / integration / simulation / visual
├─ tools
│  ├─ setup_godot.ps1 / test.ps1
│  ├─ build_windows.ps1 / verify_assets.ps1
└─ docs
   ├─ GAMEPLAY.md / THIRD_PARTY_ASSETS.md
```

- `.godot`、缓存、下载压缩包、日志、截图、测试存档和构建产物全部忽略；发布包输出到仓库外的 `D:\game_build_release\心域防线`。
- Godot 与导出模板固定版本并安装到用户工具目录，不把引擎二进制放进仓库；初始化 Git 后按功能提交。
- `RunState` 是单局唯一状态模型，保存三幕地图、持久战场、仓库、部署、耐久、资源、奖励队列、随机流游标和复盘统计。
- `ContentCatalog` 以稳定 ID 加载单位、敌人、首领、节点、收藏品、天赋和事件资源，并在启动及测试时检查引用和中文文本。
- `RuleService` 是部署、地形、视线、射程、伤害、压力、维修、融合、经验和带宽判定的唯一权威；预览与实战必须调用同一接口。
- `BattleSimulation` 使用固定逻辑步长接收命令并发出类型化战斗事件；3D表现只消费事件，不重复实现规则。
- `SeedStreams` 从单局种子派生地图、地形、首领、遭遇、奖励、商店和事件独立随机流，避免界面操作改变后续结果。
- `SaveEnvelope` 带版本号、校验值和原子写入备份；只有一个活动单局。战斗开始前保存快照，中途退出只能恢复到战前状态。

## 完整玩法与内容实现

### 三幕路线和持久战场

- 每幕采用五条横向轨道，每层2–4个节点，仅连接下一层部分节点；不能跳层或返回。
- 第一幕首层固定四个普通战斗；各幕中段保证宝库、首领前保证营地，前四层不出现精英。每条合法路线均需具备战斗、恢复和成长机会。
- 一条完整路线预计经历22–28场战斗，其余节点由营地、工坊、商店、宝库、事件和未知节点组成。
- 未知节点、商店货架、事件结果和奖励候选在生成时确定并存档，读取不能刷新。
- 三幕共用同一块25×25持久战场和单位防线。第一幕由上方入口逐渐扩展到三入口，第二幕逐渐开放四入口，第三幕从开始启用全部入口。
- 第一、二幕首领胜利后恢复20%最大精神稳定、获得幕间专注及三选一首领级收藏品；第三幕首领恢复35%后直接胜利结算。

### 战前、地形和战斗

- 完整实现 AGENTS.md 中的部署、搬迁、撤回、维修、攻击优先级、升级、融合和地形升降，并为正常、取消、失败和边界流程提供确认反馈。
- 25×25高度图严格保持0–3级和相邻高度差不超过1；火种、入口、占用格不可修改。
- 射程预览、直接视线、间接攻击、高地射程加成和低打高减伤全部来自同一规则服务；修改地形后立即刷新路径、屏障、射程和视线。
- 地面敌人使用分层寻路；正常路线被封闭时生成最低代价破障路线。飞行单位跳过地面路径，但仍可被合法对空单位选中。
- 带宽下降时按部署时间从新到旧禁用，恢复时自动启用；禁用来源、受影响单位和缺口均显示在界面。
- 死亡压力采用平滑平方衰减 `原始压力 ÷ (1 + (距离/6)²)`，再直接扣除抗性；战斗日志显示原始值、距离减免、抗性和最终伤害。
- 战斗采用1×、2×、3×与暂停；固定20 Hz模拟、60 Hz画面插值，对象池负责敌人、投射物、飘字和特效。
- 同时活动敌人上限100。召唤、复制和分裂共享一个确定性增援预算，最多为初始编队的10%，任何能力都不能绕过预算。
- 从零制定编队：第一幕普通战16–28名、第二幕24–38名、第三幕32–50名；精英和首领提高单体强度与机制密度，而非依靠塞满100名敌人。

### 构筑和内容量

- 开局固定为100精神稳定、99专注、20带宽、深度1，仓库包含三个近战、三个远程和一个支援单位。
- 制作12种基础防御单位，每类四种：

  - 近战：锚定壁垒、相位刃、边界铆钉、共振守卫。
  - 远程：脉冲针列、聚焦轨炮、弧光迫击炮、无人机织机。
  - 支援：带宽中继、记忆维修师、频率合唱器、抗性信标。

- 每个单位都有两个T2分支及对应T3终点，分别改变阻挡、反击、穿甲、间接攻击、对空、维修、强化、压力控制或带宽策略，而非只增加数值。
- 制作18种普通/功能敌人，覆盖基础推进、奔袭、飞行、护盾、治疗、加速、远程猎杀、攻城、带宽干扰、传送、召唤、复制、分裂、爆炸和抗性腐蚀。
- 制作4名精英：截频猎手、地形拆解者、增殖协议体、精神税吏。
- 制作6名首领：

  - 噪声边境：噪声母巢、镜像审查官。
  - 记忆工厂：记忆重铸机、带宽征用者。
  - 统御核心：合唱监管者、零频主脑。

- 制作30件收藏品、24项天赋和24个事件，平均分布在高地远程、近战承伤、支援网络、远距压力控制、低精神爆发、带宽扩张六种构筑主题。
- 营地、工坊、商店、宝库、未知、事件和奖励顺序严格实现 AGENTS.md 的独立作用；普通战基础获得35/40/45专注，精英获得80/90/100专注，商店维持单位80、收藏品120基础售价。
- 深度升级沿用200起步、每级增加125经验；每级增加5最大精神稳定、恢复10当前稳定、增加1带宽和1抗性，偶数深度触发天赋三选一。
- 控制压力1–10依次加入生命、攻击、困难敌人提前、功能敌人比例、营地恢复降低、死亡压力、节点服务价格、带宽干扰、首领额外招式和最终综合强化；全部在开局前明示并累计生效。

### UI、美术、音频和教程

- 主界面包含新游戏、继续游戏、图鉴、设置、制作人员和退出；新游戏覆盖活动单局前必须确认。
- 路线、战前、战斗、节点服务、奖励和结算分别使用独立界面状态，关闭面板时清理拖拽、选择和输入焦点。
- 3D镜头采用四方向吸附旋转、滚轮缩放、WASD/中键平移和一键回到火种；避免自由视角破坏格子可读性。
- 战前布局固定为顶部资源、左侧入口威胁、底部仓库、右侧单位检查器；合法性同时使用颜色、图标、文字和占地轮廓表达。
- 首三场战斗分步教学镜头、部署、带宽、地形、视线和死亡压力；教学提示只在对应操作出现，并可跳过或在图鉴重看。
- 写实工业科幻采用磨损金属、陶瓷装甲、冷色工业照明、青色火种、洋红敌意信号和琥珀专注反馈；雾效和故障特效不得遮挡路线与单位轮廓。
- 基础网格、单位和敌人使用可商用 CC0 模型重新组合和材质统一：主要来源为 [Quaternius Sci‑Fi Essentials](https://quaternius.com/packs/scifiessentialskit.html)、[Animated Mech](https://quaternius.com/packs/animatedmech.html) 和 [Modular Sci‑Fi](https://quaternius.com/packs/ultimatemodularscifi.html)；PBR材质来自 [Poly Haven CC0资源](https://polyhaven.com/license/)。
- UI和音效采用 [Kenney科幻UI](https://kenney.nl/assets/ui-pack-sci-fi) 与 [Kenney科幻音效](https://opengameart.org/content/sci-fi-sounds)。音乐采用 [Dark Sci‑Fi Audio Pack](https://opengameart.org/content/dark-sci-fi-audio-pack) 的菜单、路线、平静战斗、危急和结算循环，并为首领加入独立CC0战斗曲。
- 每个第三方文件记录原页面、作者、许可证、下载日期、哈希和项目内用途；仅保留实际引用的GLB、纹理和OGG，不提交原始压缩包。
- 音频设置提供主音量、音乐、战斗音效和界面音效；节点与战况间使用交叉淡入淡出，暂停和结算时正确降噪。

## 验证、性能与交付标准

- 单元测试覆盖地图连通性、随机复现、所有部署失败原因、多格占地、地形边界、视线一致性、破障路径、伤害下限、死亡压力、带宽禁用顺序、维修、融合耐久、升级分支、奖励顺序和存档迁移。
- 集成测试覆盖全部节点的正常/取消/资源不足流程、未知节点与商店防刷新、战斗中退出、奖励中退出、首领抵达火种后仍可被攻击，以及胜败结算。
- 对1,000个种子验证三幕地图结构；对100个种子运行完整无界面模拟，必须全部抵达胜利或失败结算且无卡死；20个基准种子使用参考策略必须可在标准难度通关。
- 压力测试使用100个活动敌人、最大可部署防线、全部增援能力和多阶段首领；GTX 1050级目标为1080p中画质平均不低于60 FPS、1%低帧不低于45 FPS。
- 实际查看菜单、三幕路线、全部节点、部署预览、地形改造、四入口战斗、六名首领和胜败结算；同时检查1080p与1366×768、100%/125%/150%界面缩放。
- 资产检查必须确认无缺失引用、许可证缺失、点击噪声、循环断点或超规格纹理；Godot启动、测试和导出过程中不得出现错误或警告。
- `tools/test.ps1` 使用隔离测试存档；`tools/build_windows.ps1` 从干净检出构建并启动发布版冒烟测试，最终验证完整标准难度胜利流程、失败流程和战中退出恢复。
- 交付前清除本次产生的缓存、日志、截图和临时包；仓库只保留源码、运行资源、测试、构建工具、许可证和必要说明。

## 明确边界与默认项

- 首发不包含多人、联网服务、语音配音、手柄、Web导出或Steam接口；不妨碍以后扩展。
- 不导入或重建任何旧项目内容，也不沿用旧单位、旧美术或旧数值；只保留“先确认真实引擎工具链”和“所有增殖能力共享上限”两条失败经验。
- 当前没有旧存档需要兼容；新工程从存档版本1开始，但所有后续结构变化必须提供显式迁移或清楚拒绝，不能静默损坏。
- “第17层最终首领”被正式替换：第17层是第一幕首领，第二幕第16层首领，第三幕第15层才是本局最终首领，其余 AGENTS.md 规则保持有效。

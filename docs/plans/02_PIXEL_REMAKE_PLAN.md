# 《心域防线》2.5D像素化整体重制计划

## 总结

- 以当前尚未提交的 `launcher/`、`development/` 目录整理为新基线，先单独保存这些用户改动，不恢复旧的根目录 `tests/`、`tools/`。
- 战斗重制参考 [Tower Dominion](https://towerdominion.com/) 的“地形决定通路、高度和火力价值”，但采用自由度更高的41×41微网格；只允许战前改造，确认开战后完全锁定。
- 地图参考《杀戮尖塔2》的[图标化分支地图](https://sts2.untapped.gg/en/guides/how-to-make-the-best-map-choices-in-slay-the-spire-2)，修复当前“同一层节点全部同类”的生成问题。
- 美术确定为2.5D像素混合：正交3D地形负责高度，单位使用像素精灵，UI全面像素化；现有开发存档全部作废。
- 战斗音乐改为克制的自适应电子氛围，替换当前刺耳的 `pulse/urgent` 循环。

## 核心改造

### 视觉、UI与音乐

- 使用640×360内部画布、最近邻采样和整数倍缩放；1080p为3倍、1366×768使用1280×720居中显示，禁止抗锯齿、雾化和强辉光造成像素抖动。
- 固定清新像素色板：深青背景、薄荷青友军、珊瑚红敌意、暖黄资源、米白文字；所有状态同时使用轮廓、图标和动画，不只依靠颜色。
- 使用 [Kenney Pixel UI Pack](https://kenney.nl/assets/pixel-ui-pack)、[Game Icons](https://kenney.nl/assets/game-icons) 和 [Input Prompts Pixel](https://kenney.nl/assets/input-prompts-pixel)，中文采用OFL授权的[缝合像素字体](https://github.com/TakWolf/fusion-pixel-font)。
- 将现有CC0三维单位从8个方向自动烘焙为透明像素精灵图；运行时只加载PNG图集，原GLB保留在开发资产区供重新烘焙且不进入发布包。
- UI采用“极简图标常驻、上下文信息展开”：顶部仅显示精神、专注、带宽、敌群进度；底部为单位和地形工具栏；检查器、威胁详情和数值解释只在选择、悬停或警报时出现。
- 地图节点改用独立16×16像素图标：战斗、精英、营地、工坊、商店、宝库、事件、未知和首领各有不同轮廓；完成、可达、锁定状态使用图标叠层表达。
- 战斗音乐采用CC0的 [Singularity calm/action](https://opengameart.org/content/singularity-0) 双版本：危险度平滑控制等功率交叉淡化，首领沿用低频强化的action层，不再使用尖锐独立曲目。
- 音乐统一至约-18 LUFS、真峰值不高于-1 dB；战斗音乐总线削弱6 kHz以上高频并增加限幅器。危险度上升1.5秒、下降4秒，避免频繁跳变。

### 镜头与操作

- 相机改为固定55°俯角的正交相机；Q/E按住后以90°/秒连续改变水平偏航角，可完整360°旋转，不再吸附四方向。
- WASD严格按屏幕方向移动：W永远向屏幕上方、S向下、A向左、D向右；每帧将相机右向量和投影到地面的前向量重新组合，修复当前前后符号错误。
- 中键拖动同样使用屏幕坐标换算；滚轮调整正交尺寸；F回到醒觉火种。右上角常驻极简方向罗盘，避免自由旋转后迷失入口方向。
- 单位八方向帧根据“移动方向相对当前相机偏航角”选择，确保连续旋转时敌人朝向正确。

### 41×41微网格、高度与战斗

- `RunState` 使用41×41 `terrain_grid` 替换旧高度数组。每格保存高度0–4、斜坡方向和保护标志；醒觉火种改为5×5区域，普通单位主要使用2×2占地，大型单位使用3×2或3×3。
- 战前提供单格、3×3、直线三种笔刷，以及升高、降低、铺设/旋转斜坡和铲平工具。升降及斜坡每格消耗2专注，批量操作按实际变化格数累计。
- 每次笔刷操作以 `TerrainCommand` 事务执行，确认前显示费用、修改格、入口路径、峭壁和受影响射程；战前支持逐步撤销并原额退款。开始战斗后清空撤销栈并锁定全部地形、部署和成长操作。
- 相邻等高格可通行；高度差1只有正确方向斜坡可通行；其余边缘形成可破坏峭壁。封路时敌人选择总代价最低的破障路线，逐级击毁高侧地形并永久降低该格。
- 高地规则统一为：射手每高于目标一级获得8%射程和10%伤害，最多四级；低打高每级减少12%伤害，穿甲只能减半该保护；直接攻击统一执行插值视线检测，间接攻击只检查射程。
- 普通战、精英战、首领战分别把现有编队拆成3、4、5个连续敌群，间隔4–6秒但不开放重新部署；精英位于倒数第二群，首领位于第四群。界面提前显示每群入口、类型和到达时间。
- 100敌人上限和初始编队10%共享增援预算继续保留；所有路径、预览和实战仍由同一个 `RuleService` 计算。

### 路线地图与数据接口

- 地图拓扑先生成、节点类型后分配。随机流改为按稳定节点ID取值，禁止继续用“幕+层”共用一次随机结果。
- 第一层四个普通战斗、倒数第二层单一营地、最后层单一首领作为明确例外；其他拥有多个节点的层至少包含两种节点类型。
- 宝库只占中段某个节点，不再让整层都成为宝库；前四层无精英；同一路线不连续出现商店、工坊或营地；所有节点必须可从起点抵达并能继续抵达首领。
- 连接改为像素虚线，当前可走路径高亮、已走路径实线化、不可达路径降低对比度；悬停卡片显示图标、名称、风险、收益和下一步连接，不直接展示内部节点ID。
- 新增接口：
  - `RunState.terrain_grid`、`terrain_revision` 和新版地图节点数据，旧版 `heights` 停止使用。
  - `RuleService.validate_terrain_command()`、`apply_terrain_command()`、`solve_attack()` 和新版 `path_to_core()`，预览与模拟共用结果。
  - `BattleSimulation` 输出敌群索引、下一群倒计时和0–1危险度，供HUD与自适应音乐消费。
  - 内容目录为单位增加 `sprite_id`，为路线节点增加 `map_icon_id`。
- 存档版本提升到2；检测到任何旧活动单局或旧开发档案时直接重置，并仅显示一次“开发版本结构已更新，旧存档已清除”的说明，不编写兼容迁移。

## 实施顺序

1. 先保存当前目录整理改动，再建立像素主题、字体、图标、正交镜头和一个可旋转的战场纵切面。
2. 完成41×41地形模型、笔刷事务、斜坡/峭壁路径与统一高度判定，再迁移部署和战斗模拟。
3. 重写地图生成和图标地图，随后将全部单位、敌人和首领烘焙为像素图集。
4. 接入自适应音乐、像素VFX和极简HUD，完成内容平衡、文档、授权清单与Windows发布。
5. 删除不再引用的3D运行资源、旧战斗音乐和旧UI纹理；开发源素材及烘焙工具保留在 `development/`，发布包只保留实际运行资源。

## 测试与验收

- 对1,000个种子检查地图连通、节点多样性、固定首层/营地/首领、精英限制、奖励防刷新和所有节点可达性。
- 覆盖41×41边界、各类笔刷、撤销退款、保护格、多格占地、斜坡方向、可破坏峭壁、封路破障和地形永久损坏。
- 对所有高度差验证预览与实战的射程、视线、伤害和穿甲结果完全一致。
- 在0°、45°、90°、225°和359°视角验证WASD屏幕相对移动；验证Q/E连续旋转、角度环绕、缩放与回到火种。
- 覆盖战斗三至五敌群、危险度音乐交叉淡化、暂停降噪、循环接缝、峰值与长时间高频疲劳检查。
- 重新执行100个完整无界面模拟、20个标准难度参考种子和100敌人压力测试；41×41路径刷新不得造成模拟卡顿。
- 实际检查菜单、地图、战前笔刷、四入口战斗、全部首领和结算；覆盖1920×1080、1366×768及125%/150% Windows缩放有效区域。
- 视觉验收要求：地图不再出现单字节点；除三个明确固定层外，不出现整层同类节点；核心资源无需展开即可识别；单位、地形高差和敌人路径在一秒内可读。
- GTX 1050目标仍为1080p中画质平均60 FPS、1%低帧45 FPS；最终发布必须零脚本错误、零缺失资源、零Godot警告。

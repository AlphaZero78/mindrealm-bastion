# 构造与敌人的模型和动作

本次更新使用 CC0 Kenney GLB 零件重新组合机械模型，并用 Blender 离线烘焙带关节姿态的八方向图集。游戏仍使用本地 Canvas 渲染；模型零件、烘焙配方和许可证保留在源码中，不需要安装 Blender 才能游玩。

## 可见内容

| 内容 | 模型变化 | 动作与状态 |
| --- | --- | --- |
| 12 种防御构造 | 每种独立的 T1、T2A、T2B、T3A、T3B，共 60 种组装外观 | 盾牌/近战部件出手，炮管后坐，迫击炮抬升，无人机发射，维修臂和支援机构展开 |
| 18 种普通敌人、4 种精英 | 按实际职责区分装甲、护盾、履带、步足、发射器与信号设备 | 四姿态步行、履带悬挂/虫体节段运动、飞行姿态、攻击与能力蓄力/释放 |
| 6 种首领 | 每名首领三阶段，共 18 种外观；阶段增加护板、环带或机械附属结构 | 三阶段均包含移动、攻击、蓄力与释放姿态，头顶保留阶段标记 |

总计 40 类实体、100 种模型变体、8000 个动作方向帧。构造使用偏薄荷色能源部件，敌人使用珊瑚色信号部件；轮廓和机械结构承担主要区别。仓库、图鉴、单位详情、升级分支预览和实际战场使用对应模型。

近战采用短弧命中反馈，直射采用射线，迫击炮采用弧线，无人机使用短航迹，连锁攻击显示折线，维修显示连接与十字。被击中单位短暂闪亮；被击败敌人留下最多 0.65 战斗秒的消散形态；损毁构造保持可维修残骸。过载停机保留位置和耐久，同时停止动作并显示“停机”。

## 动作与规则的一致性

`web/core/battle.js` 在已有战斗事件上附带实体身份、目标、世界坐标、朝向和战斗时间。演出不反向决定命中、伤害、移动、技能冷却或随机结果。支援周期只增加供画面使用的静默事件，不新增声音触发。

`web/view/entity-motion.js` 只持有表现状态，不修改单局或使用随机数。行走相位来自实际移动距离；地面敌人停下后不会原地踏步。攻击、施法、受击、生成和消散采用模拟时间，暂停冻结，1/2/3 倍速同步。真实技能倒计时使用 `castUntil`，避免沿用更长的提示时间。普通攻击的短姿态序列呈现已发生的出手，不增加新的攻击前摇或改变伤害时点。

“减少动态效果”关闭行走循环、飞行循环、受击位移、生成缩放和额外粒子；仍保留静态攻击/施法姿态、命中连线、蓄力标记、停机及首领威胁范围。该选项是游戏内设置。

场景更换、战前读档或模拟时钟回退会清理旧动作、射线和消散快照。塔的占地、射程、视线、带宽与敌人命中位置仍由核心规则计算；命中特效根据同一坐标加上模型的视觉高度，包含飞行目标。

## 资源合同与复现

`web/view/entity-art.js` 定义共享尺寸和路径。每格 80×80，八个方向，55° 正交视角，正面对应世界 +Z，基线为格高的 72%。每种变体有 10 行：静止 0，移动 1–4，攻击 5–7，施法 8–9。塔的五种变体按 T1、T2A、T2B、T3A、T3B 排列；首领按阶段 1–3 排列。

- `assets/game/sprites/animations/`：40 张动作图集，宽 640，塔高 4000，首领高 2400，其他敌人高 800。
- `assets/game/sprites/towers/`、`enemies/`：40 张界面图集，直接提取每种变体的静止行，避免图标与战场不一致。
- `development/assets/model_sources/kenney/`：本次配方实际引用 49 个 GLB，合计 1,059,592 字节；其中 Space Kit 41 个、Tower Defense Kit 8 个，均保留 CC0 许可。
- `development/web-tools/bake-entity-art.py`：零件组合、分支/阶段结构、关节姿态、材料和相机配置的源码。
- `development/web-tools/inspect-entity-art.py`：尺寸、空帧、透明边界、姿态差异、变体差异、重复轮廓与静止行一致性检查，生成接触图和动作 GIF。
- `development/web-tools/measure-entity-bounds.py`：从透明像素边界生成 `bounds`、`iconBounds` 和 `minVisibleSpan`，不改变 PNG。战场保留完整帧和统一基线；界面使用 SVG viewBox 裁去图集留白，升级分支共享取景范围。

战场按模型全姿态范围确定显示尺度。普通敌人、精英与首领每一帧的可见最长边分别至少为 20、26、38 CSS 像素；同类型在所有姿态和方向下使用相同尺寸，不逐帧放大缩小。构造使用 28 像素的全变体范围下限，保留 T1 到 T3 的结构成长比例。世界占地和镜头坐标不变，血条与状态标记依据实际图像边界安置。

最终烘焙使用 Blender 4.5.9，全部 PNG 合计 33,561,545 字节（约 32.01 MiB）。完整解码约 214.84 MiB，尚不包括浏览器附加缓存；压缩文件大小不能代表运行内存。

```powershell
# Blender 和检查脚本的 Pillow 环境放在项目外。
& '路径\blender.exe' --background --python .\development\web-tools\bake-entity-art.py -- --output "$env:TEMP\mindrealm-entity-art"
python .\development\web-tools\inspect-entity-art.py --source "$env:TEMP\mindrealm-entity-art" --output "$env:TEMP\mindrealm-entity-art-qa"
# 批准复制资源后，测量并同步显示元数据；只修改生成块。
python .\development\web-tools\measure-entity-bounds.py --output "$env:TEMP\mindrealm-entity-bounds.json" --write-metadata
```

烘焙输出只能放在仓库外；逐帧检查和实际浏览器视觉检查通过后，才复制需要的 PNG 到运行资源目录。随后执行 `node development/web-tools/refresh-asset-manifest.mjs --write`、`npm test`、`npm run verify`。Blender、下载压缩包、中间场景、截图、GIF和报告均不进入发布包。重新烘焙可能受 Blender 版本和抗锯齿实现影响，不能假设不同版本会产生相同 PNG 哈希。

## 验证

验证脚本使用独立回环端口和 `?qa=1` 内存存储，禁止连接玩家的 4173 站点。`browser-entity-animation.js` 同时保留旧版基线与新版验收模式，模型接触图明确标为展示帧；真实战斗的逐帧动作、暂停和倍速另行采样。`browser-full-run.js` 验证路线、节点、奖励与结算闭环，脚本推进与真实 RAF 画面证据分别记录。

资产终态：40 类、8000 动作格通过，最小透明边界 4 像素，无空格、裁切、重复首阶轮廓或重复升级/阶段变体；界面静止行与动作图集对应行像素一致。节点测试覆盖时钟冻结、升级/阶段行选择、停机、飞行命中高度、消散清理和读档重置。

核心事件兼容检查：69 个场景、43,443 个模拟步、11,108 个原有事件的值、数量和顺序一致；覆盖全部 12 塔、28 敌人以及旧/新难度规则。0 与 10 压力的参考远征均完成 48 节点，空防线按预期失败。此项说明事件桥没有改变规则结果，不能替代模型和动作的浏览器检查。

最终源码构建：167 项 Node 测试通过，116 项必要资源、173 项 SHA-256 清单项通过，便携包包含 132 个内容文件和 1 份发行清单。浏览器动作验收 29 项通过，包含真实 T2A/B 模型预览、取消后单局不变、确认 B 分支、T3B 唯一升级方向，以及菜单继续后恢复同一 T2B 部署模型。暂停时间误差为 0；1/2/3 倍速样本分别为 0.998/2.000/3.041。1920×1080 和 960×540 的模型、图鉴、升级弹窗均实际查看。

浏览器完整流程以 `reference-0`、压力 0 通过 48 节点，击败噪声母巢、记忆重铸机、合唱监管者并显示胜利结算，画面与音频错误列表为空。每幕普通战和首领战分别采集真实 RAF 动作，包含阶段切换、支援释放、攻击和死亡；六段样本的动作时钟误差均为 0。其余较长战斗使用内存 QA 的固定步长推进检查流程，不据此冒充完整实时人工通关。最后的四角选择框与高度快照修正另有回归检查。

最终 960×540 浏览器烟测验证了合法放置预览、取消不改动单局、选择角框准确包围放大后的主体、飞行实体使用规则高度，以及消散快照保留死亡时高度，未出现画面或音频错误。便携版 132 项清单全部匹配，19 个 Web 源文件和 80 张 PNG 与源码逐字节一致；中英文根启动入口均使用包内 Node，运行包不含 Godot 或 GLB 依赖。

独立便携 UI 验收 22 项通过：从标准 100 精神、99 专注、20 带宽的新局合法部署 19 带宽的五座构造，检查保护区拒绝、取消不改状态、开战确认取消、真实攻击和暂停，再从菜单继续恢复相同战前位置、耐久、资源与地形。40 张动作图全部解码，79 个请求均为本地资源，没有外网请求或运行错误。验证脚本为 `browser-portable-entity.js`，证据存于系统临时目录 `mindrealm-portable-final`；正式实战截图位于发布目录外的 `D:\game_build_release\entity-models-preview.png`。

### 高压力画面对照

2026-09-05，Chrome 152、RTX 5060 Laptop、1920×1080 窗口、1670×717 战场、DPR 约 1、中等画质。每组 1000 个 RAF 帧，35 座塔、100 个敌人（含 6 首领），位置、阶级、分支、敌人名单和设置一致。

| 场景 | 旧静态版平均 FPS | 新动作版平均 FPS | 旧/新 1% low | 旧/新绘制均值 |
| --- | ---: | ---: | --- | --- |
| 连续旋转、射程轮廓、地形缓存每秒失效 4 次 | 91.09 | 78.35 | 57.08 / 54.59 | 3.00 / 4.05 ms |
| 实际移动、攻击、治疗、施法与首领动作 | 90.10 | 84.54 | 52.41 / 54.32 | 3.30 / 4.08 ms |

两组均保持指定实体数量并且零错误。移动组为持续压力展示场景，只维持耐久并将接近火种的敌人收回测试起点，以持续观测原有行为；它不作为正常胜率或平衡证据。运行期存在少量帧率波动，单次样本只代表描述性对照，不能视为所有设备上的性能保证。采样后还修正了蓄力文字、选择框和敌人高度坐标；这三项位置修正由针对性测试与最终浏览器烟测验证，没有据此重复整组 FPS 测量。

40 张战场动作图首次就绪约 368.5 ms（旧版 120.7 ms），其中显式解码等待约 268.6 ms（旧版 20.9 ms）。这 40 张动作图解码为 195.31 MiB，连同全部界面图集约 214.84 MiB。操作系统记录的浏览器主渲染进程峰值工作集约由 254.4 MiB 增至 618.5 MiB，GPU 进程由 163.0 MiB 增至 336.1 MiB；这是各进程单独峰值，不能相加称为同时总峰，也不能当作显存用量。新模型的主要代价是图集解码及浏览器缓存占用，不能只根据 32 MiB 的 PNG 大小判断内存需求。

原始性能数据、截图和对照存于系统临时目录 `mindrealm-entity-performance`；美术像素检查存于 `mindrealm-entity-art-qa`，动作与 UI 检查存于 `mindrealm-entity-acceptance`。长期保留的是上述方法与脚本，临时结果不进入源码或便携包。

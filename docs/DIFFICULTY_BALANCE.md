# 控制压力 0–10：规则与平衡记录

本文保留规则修订 2 的参数与历史验收记录。当前新局采用修订 3，标准敌人成长、经验、升阶、中继和道具规则见[平衡与背包更新](BALANCE_INVENTORY_UPDATE.md)。下文表格中的压力级别倍率继续适用；历史胜率仅对应当时的实现。

难度的唯一来源是 [difficulty.js](../web/core/difficulty.js)：`difficultyProfile` 提供累计参数，`enemyStats` 计算本场敌人属性，`enemyAbilityProfile` 与 `enemyRecoveryBase` 计算能力、治疗和护盾，`difficultySummary` 生成玩家可见说明。界面与实战应共同读取这些函数。

## 选择与解锁

初始开放压力 0。通关某级后，开放下一级，最高 10；此前已解锁等级不会降低。玩家在新远征确认前选择已开放等级，并查看该级的累计数值和机制。局外解锁不提高开局基础属性。

新版将压力集中在敌人强度和可预判的战斗机制上。所有等级的营地仍恢复最大精神的 30%，商店、维修和升级不再因压力等级加价；收藏品、天赋与原有维护规则仍按其描述生效。

这明确替代原计划中的高压营地削弱、服务加价、提前投放后续幕敌人及提高功能敌人槽位比例。玩家能继续利用营地、维修和分支成长处理战损，并在相同编队上比较防线的承压能力。强敌也不再因为提前进入编队而额外补贴经验与专注。两份原计划保留作为历史设计记录。

## 编队、奖励与数量边界

对同一种子、内容池和节点，新版各压力等级使用相同的计划敌人类型、入口分配、出场时间、群数、数量，以及每种敌人的击杀经验和专注掉落。压力不会额外发奖励，也不会提前把下一幕敌人塞进当前编队。

普通、精英和首领战仍有 3、4、5 群；同时活动敌人最多 100 名，召唤、复制和分裂共用 `floor(计划敌人数 × 0.1)` 的增援预算。实战中能否及时击杀、实际产生多少增援、存活到哪一节点及选择哪条路线，仍可能随策略与难度变化。因此不能用两局的最终敌人总数不同，推断同节点编队发生了变化。

奖励的种子规则和保存方式保持原样。路线、击杀、成长次数或已经拥有的收藏品不同，会改变整局领取的奖励数量或后续候选；“击杀奖励一致”不表示不同操作的两局必须领取完全相同的全部奖励。

## 首领、频震与干扰

首领生命使用表中的完整倍率，但所有来源的首领治疗与护盾按其平方根倍率增长。例如压力 10 的生命为标准的 3.20 倍，恢复数值约为标准的 `sqrt(3.2) = 1.789` 倍。普通治疗或护盾敌人支援首领时也使用这个恢复基数，避免绕过限制。

单个干扰来源的持续时间按当前阶段常规能力周期限制，留下至少 1.1 秒恢复间隔。多个来源仍可能重叠，阶段切换也有独立节奏；这不是全战场同时免疫干扰的保证。抗扰中继、干扰抵抗、预留带宽和优先击杀干扰者仍有作用。

压力 8–10 的所有首领新增频震：

- 每 12 秒一个周期，释放前预警 1.5 秒；蓄力时停留在已标记的位置。
- 在首领 8 格范围内锁定最多两座存活构造，已启用的嘲讽构造优先，其次按距离选择。
- 对仍在标记范围内的目标造成首领攻击力 55% 的攻击伤害，继续经过护甲、穿甲、高地保护及相关防护结算。
- 这是额外的已公开能力，不增加敌人数或增援预算。战斗中不能重新部署，玩家须在战前安排承伤者、侧翼射手、维修覆盖和带宽余量。

战前情报显示本场真实敌人属性与能力；图鉴区分基础资料和当前战斗数值，避免把目录基础生命当作高压实战生命。

## 旧局兼容

新建远征写入 `difficultyRevision: 2`。已有 Web v2 单局若缺少该字段，或者明确为 1，按旧版控制压力继续；读取、保存或开始下一场战斗不会悄悄切换难度规则。旧局仍保留当时的提前敌人、营地与服务惩罚等累计效果，界面说明其旧规则身份。

存档结构版本和正式命名空间仍为 `version: 2`、`mindrealm.web.v2`。本次不重置路线、地形、仓库、耐久、货架、奖励、内容池、记忆碎片或已解锁压力；`runId` 和已结算记录继续用于防止重复领取。未知的规则修订号会被拒绝读取为有效单局，原始数据保留。Godot 与 Web v1 的不兼容记录不属于此次难度修订的自动迁移范围。

## 评测方法与已取得结果

以下为**固定脚本策略在指定种子上的样本**，不是人类玩家胜率，也不证明某一策略最优。所有模拟使用纯 `newRun` 内存状态和公开的部署、维修、升级、节点、奖励命令，不读取玩家存档，不赠送资源、不改变随机结果。参考策略侧重 A 分支中继扩张与远程输出；防守策略侧重最多两座 B 分支中继、2–3 名前排、维修覆盖、侧翼远程和带宽余量。

“累计精神伤害”为死亡压力、突破及事件伤害总账，治疗不会从中扣除；致命伤可能包含超过剩余精神的部分。平均每战时长是模拟战斗秒数，不是 CPU 耗时。高难度早败会缩短可累计的损失与节点数，不能仅按全局伤害大小排序难度。

## 重现与后续校准

从项目根目录使用 [difficulty-sweep.mjs](../development/web-tools/difficulty-sweep.mjs)：

```powershell
$seeds = (0..2 | ForEach-Object { "reference-$_" }) -join ','
node .\development\web-tools\difficulty-sweep.mjs --levels 0,5,10 --seeds $seeds --strategy defensive --workers 2 --output "$env:TEMP\mindrealm-difficulty-defensive.json"
```

`--levels` 接受逗号列表或 `0-10`；`--seeds` 接受逗号分隔的种子；`--strategy` 为 `reference`、`defensive`、`opening`、`empty`；`--workers` 为 1–4，默认 2。报告必须写在仓库外。成功需退出码 0、最终 `DIFFICULTY_SWEEP.ok: true`，并核对 `changed`、`failures`、`countMismatches` 都为空；单级评测的跨级 `countChecks` 为 0 是正常结果。

工具检查完整种子地图的已知战斗节点，以及实际到达的同名节点；比对计划总数、群数、入口分配与增援预算。每局保存幕层、逐战时长、计划/实际敌数、压力/突破/事件损失、摧毁、成长、带宽与关键构筑。`safeBandwidth` 排除已结束战斗残留的临时干扰，`bandwidth` 保留当时状态供复盘。

后续应同时查看各级通过率、败局发生位置、精神来源、构造损毁和不同首领表现。相同种子共用条件，样本之间并非独立玩家。若某级出现明显断层，应先检查具体敌人或机制；不应只为提高脚本胜率修改策略、赠送资源或降低模拟频率。完整命令与隔离浏览器方法见 [开发说明](DEVELOPMENT.md)。
